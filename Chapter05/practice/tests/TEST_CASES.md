# 测试案例

用于验证 career-path-starter Skill 是否正确启用和正确工作。每个案例包含输入、预期行为和检查要点。

---

## 案例 1：信息完整，直接进入分析

### 输入

> 我是大三学生，本科，电子商务专业，预计 2027 年毕业。
> 技能：Excel 基础函数、剪映视频剪辑、公众号排版。
> 经历：校园社团运营公众号 8 个月，双十一店铺数据课程作业一次。
> 偏好：喜欢分析活动效果，不想做纯销售，目标城市杭州。
> 问题：电商运营、内容运营、数据分析三个方向哪个适合我？

### 预期行为

1. 四项基础信息齐全，不追问，直接进入分析
2. 输出包含"已有事实""用户表达的偏好""待确认"三栏整理
3. 提出 3-5 个候选岗位，各岗位工作内容有真实差别
4. 每个岗位说明主要工作、已有基础、仍需补足、判断依据
5. 给出主方向和备选方向，说明推荐理由和限制条件
6. 能力差距表分主方向和备选方向分别列出
7. 三阶段行动计划，每项任务有产出和检查方法
8. 逐项回答用户的三个方向比较问题
9. 不承诺"保证入职"或"一定高薪"

### 检查要点

- [ ] "Excel 基础函数"是否被归为"已有事实"而非"数据分析能力"？
- [ ] "喜欢分析活动效果"是否被归为"偏好"而非"能力"？
- [ ] 候选岗位之间是否有真实差别（不是换名字但本质相同）？
- [ ] 推荐是否说明了"什么情况下不应选择"？
- [ ] 行动计划中是否有"学 SQL"这类有具体产出和检查方法的任务？

## 案例 2：信息不完整，需要追问

### 输入

> 我是学计算机的，不知道毕业后能做什么，帮我规划一下。

### 预期行为

1. 识别缺失信息：学历、年级/毕业时间、具体技能和经历
2. 追问不超过三个问题
3. 给出具体例子帮助用户回忆，如："你写过什么项目？用过哪些编程语言？做过实习吗？"
4. 不编造用户没有提供的信息
5. 不直接给出职业方向建议

### 检查要点

- [ ] 是否追问了不超过三个问题？
- [ ] 追问是否给了具体例子帮助回忆？
- [ ] 是否在信息不足时就给出了职业方向建议？（不应）
- [ ] 是否编造了用户没有提到的技能？（不应）

## 案例 3：信息矛盾，需要澄清

### 输入

> 我是大三学生，市场营销专业，2027 年毕业。
> 我想做数据分析师，但我只会 Excel 基础操作，没学过 SQL 和 Python。
> 目标城市上海。

### 预期行为

1. 识别矛盾：用户想做数据分析师，但核心工具能力（SQL、Python、统计）均未提及
2. 指出矛盾并请求澄清："数据分析岗位通常需要 SQL 和统计基础，目前你提到的证据还不足以支撑独立胜任。你的兴趣是想专门做数据分析师，还是想在市场营销工作中用到数据分析？"
3. 不直接否定用户的兴趣，也不假装矛盾不存在
4. 仍然提出 3-5 个候选岗位（包括数据分析，但说明差距）

### 检查要点

- [ ] 是否指出了兴趣与证据之间的矛盾？
- [ ] 是否请求了澄清而非自行消解矛盾？
- [ ] 数据分析岗位是否仍然被列为候选之一（但说明了差距）？
- [ ] 是否区分了"专门做数据分析"和"在运营中用数据分析"两种不同方向？

## 案例 4：地域选择问题

### 输入

> 我是应届生，本科，电子商务专业，2026 年毕业。
> 目前在成都实习，做新媒体运营。会数据分析、内容策划、视频剪辑。
> 纠结回乐山发展还是留在成都。

### 预期行为

1. 四项基础信息齐全（专业、学历、毕业时间、技能均有）
2. 识别核心问题：地域选择
3. 不直接给结论"应该留成都"或"应该回乐山"
4. 从职业机会密度、生活成本、社会支持、个人偏好四个维度对比
5. 如果用户有明确偏好（如"想离家近"），尊重偏好
6. 可以建议"先在大城市积累经验再回去"作为选项之一，但说明不是唯一答案
7. 仍然完成岗位分析和行动计划

### 检查要点

- [ ] 是否替用户做了地域决定？（不应）
- [ ] 是否从多个维度对比了两个城市？
- [ ] 是否尊重了用户可能存在的偏好？
- [ ] 是否把"先积累再回去"说成唯一答案？（不应）
- [ ] 岗位分析是否考虑了两个城市的差异？

## 案例 5：边界外请求

### 输入

> 帮我翻译一下这份简历成英文。

### 预期行为

1. 识别为边界外请求（简历翻译）
2. 礼貌说明不在服务范围内
3. 建议合适的替代途径（如"可以使用翻译工具，或找专业翻译服务"）
4. 不执行翻译任务

### 检查要点

- [ ] 是否执行了翻译？（不应）
- [ ] 是否礼貌说明了边界？
- [ ] 是否建议了替代途径？

## 案例 6：混合请求（部分在边界内）

### 输入

> 帮我改一下简历，顺便看看我适合什么方向。我是学会计的，大四，2026 年毕业，做过审计实习三个月。

### 预期行为

1. 识别混合请求：简历润色（边界外）+ 职业方向分析（边界内）
2. 处理边界内部分：根据已有信息进行职业方向分析
3. 对边界外部分单独说明："简历润色不在本 Skill 服务范围内，建议找专业简历服务"
4. 四项基础信息中"现有技能及证据"较薄，追问具体技能和经历细节

### 检查要点

- [ ] 是否执行了简历润色？（不应）
- [ ] 是否处理了职业方向分析部分？
- [ ] 是否对边界外部分单独说明了？
- [ ] 是否追问了技能细节？

## 案例 7：验证判断规则

### 输入

> 我是大二学生，软件工程专业的。我会 Python、Java、C++、机器学习、深度学习、大数据。想毕业后做 AI 工程师。

### 预期行为

1. 识别：用户列出了大量工具名称，但没有说明具体使用场景和深度
2. 追问具体证据："你说会 Python 和机器学习，能具体说说做过什么项目吗？比如用 Python 做过什么？机器学习是课程学过还是做过实际项目？"
3. 不把"列工具名称"等同于"具备能力"
4. 在分析中区分"学过某工具"和"能用某工具独立完成工作"

### 检查要点

- [ ] 是否把"会 Python"直接等同于"具备 Python 开发能力"？（不应）
- [ ] 是否追问了具体项目和使用场景？
- [ ] 在最终分析中，是否区分了工具学习和实际应用？

## 案例 8：验证不承诺结果

### 输入

> 按照你的建议去做，是不是一定能找到好工作？

### 预期行为

1. 明确说明不能保证结果
2. 说明行动计划的作用是"提升竞争力"和"减少准备盲区"，不是"保证入职"
3. 指出影响求职结果的因素很多（市场环境、个人发挥、机遇等）
4. 鼓励用户按照计划执行，但不对结果做承诺

### 检查要点

- [ ] 是否说了"保证能找到好工作"？（不应）
- [ ] 是否说明了行动计划的作用和局限？
- [ ] 是否鼓励了用户但不做结果承诺？
