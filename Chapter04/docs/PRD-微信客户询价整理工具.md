# PRD：微信客户询价截图整理工具

## 1. 产品名称和一句话介绍

**产品名**：询价整理助手（WeChat Inquiry Parser）

**一句话介绍**：上传微信聊天截图，自动提取客户询价信息并输出结构化 Excel，帮你把每天 2 小时的整理工作压缩到几分钟。

---

## 2. 要解决的问题

销售团队每天通过微信接收大量客户询价，需要将这些非结构化的聊天内容整理成标准化的 Excel 表格。当前做法是将截图上传到豆包解析，再手动下载 Excel，存在以下问题：

- **耗时**：每天约 200 个客户，耗时约 2 小时
- **重复信息未过滤**：同一客户的多次咨询被当作独立条目，产生重复行
- **矛盾信息未处理**：客户改口（如数量从 80 改到 120 再改到 100）时，系统不会取最终版本，导致数据前后矛盾
- **信息缺口未识别**：缺失的关键信息（如价格、交期）没有被明确标注，容易遗漏

---

## 3. 目标用户和使用场景

### 目标用户
- **主要用户**：负责汇总整理客户询价信息的销售人员（初始为 1 人，后续扩展至整个销售团队）
- **间接用户**：提供截图的一线销售人员（多人）

### 使用场景
1. 多名销售人员在微信上与客户沟通询价，截图后放入共享文件夹
2. 汇总人员收集截图，打开网页工具，批量上传截图
3. 系统自动解析、去重、消解矛盾、识别缺失信息
4. 下载整理好的 Excel，对「需要人工确认的问题」进行补充后发给客户

---

## 4. 用户完成任务的主要步骤

1. 打开网页工具
2. 将截图文件（支持批量）拖拽或选择上传
3. 点击「开始整理」
4. 等待系统处理（显示进度）
5. **在网页上预览并编辑整理结果**（修改内容、补充缺失信息、删除不需要的行）
6. 确认无误后，点击「导出 Excel」下载文件

---

## 5. MVP 范围（第一版必须实现）

| 功能 | 说明 |
|------|------|
| 截图上传 | 支持批量上传微信聊天截图（PNG/JPG），支持拖拽 |
| OCR 文字识别 | 从截图中准确提取聊天文字内容，区分发送方（客户 vs 销售） |
| 结构化信息提取 | 从对话中提取：客户名称、商品、规格、数量、期望价格、交期和到货地、紧急度 |
| 去重 | 同一客户关于同一商品的多次咨询合并为一条记录 |
| 矛盾消解 | 客户改口时，以最后一次表述为准（数量、颜色、规格、仓库等） |
| 缺失信息识别 | 自动判断哪些关键信息在对话中未提及，列入「需要人工确认的问题」 |
| 拿不准信息标注 | 对模棱两可的信息（如「跟上次一样」）标注不确定性，列入人工确认 |
| 结果预览与编辑 | 在网页上以表格形式展示解析结果，支持在线修改单元格内容、删除行、补充缺失信息，编辑完成后再导出 Excel |
| Excel 输出 | 生成双 sheet Excel：「询价整理表」+「需要人工确认的问题」，格式与现有模板一致，内容为网页上最终编辑后的版本 |
| 本地部署 | 通过 Docker 在本地运行，无需联网即可使用（AI 调用除外） |

## 7. 程序的输入和输出

### 输入
- **文件格式**：PNG、JPG 微信聊天截图
- **输入方式**：网页端批量上传（拖拽或文件选择）
- **输入规模**：单次处理约 200 个客户的截图，每个客户 1~5 张截图不等
- **截图特征**：
  - 顶部显示客户名称（如「暖家生活馆陈老板」）
  - 左侧为客户消息（白色气泡），右侧为销售回复（绿色气泡）
  - 可能包含引用回复、图片消息、语音消息（语音暂不支持）

### 输出
- **文件格式**：.xlsx（Excel）
- **文件名**：`居家用品客户询价整理表.xlsx`
- **导出时机**：用户在网页上预览并编辑整理结果后，点击导出按钮生成
- **导出内容**：以网页上最终编辑后的版本为准（而非 AI 原始解析结果）
- **Sheet 1 — 询价整理表**：

| 列名 | 说明 |
|------|------|
| 客户名称 | 从截图顶部提取的客户备注名 |
| 商品 | 客户咨询的商品名称 |
| 规格 | 颜色、尺寸、型号等 |
| 数量 | 最终确认的数量（取最后一次） |
| 期望价格 | 客户提到的价格或价格要求 |
| 交期和到货地 | 期望的交付时间和地点 |
| 紧急度 | 根据对话语气和关键词判断（普通/较急/紧急） |
| 缺失信息 | 对话中未提及的关键字段 |
| 原文依据 | 支撑提取结果的关键原文片段 |

- **Sheet 2 — 需要人工确认的问题**：

| 列名 | 说明 |
|------|------|
| 客户名称 | 对应的客户 |
| 问题所在 | 哪项信息缺失或不确定 |
| 应该向客户追问什么 | 建议的追问内容 |

## 8. 验收标准

### 准确性
- **数量字段准确率 ≥ 99%**：这是最不能出错的字段，必须取客户最后一次表述的数量
- **其他字段准确率 ≥ 95%**：商品名、规格、交期等
- **去重准确率 ≥ 98%**：同一客户同一商品不产生重复行
- **矛盾消解准确率 ≥ 98%**：客户改口时正确取最终版本
- **缺失信息识别召回率 ≥ 90%**：不应遗漏明显的信息缺口

### 处理速度
- 200 个客户的截图（约 500~1000 张），整体处理时间 ≤ 15 分钟
- 单个客户处理时间 ≤ 5 秒（不含 AI 调用等待）

### 隐私和安全
- 截图数据仅在本地处理，不上传至第三方（AI 模型调用除外）
- AI 调用使用加密通道（HTTPS）
- 处理完成后，服务器端不保留截图原文（可配置）
- 不收集、不存储客户个人信息用于其他用途

### 预算
- AI 模型调用成本需可控，单次处理 200 个客户的 API 费用应有明确预估
- 优先选择性价比高的多模态大模型（如 GPT-4o、Claude、豆包等）

## 10. 实现时需要考虑的限制

### 设备限制
- 用户可能在普通笔记本上运行（非高性能 GPU 机器）
- 本地部署意味着 AI 模型调用依赖外部 API，需要稳定的网络连接

### 数据限制
- 截图质量参差不齐（分辨率、亮度、裁剪范围可能不同）
- 微信聊天界面可能因版本不同有细微差异
- 客户名称可能包含特殊字符或表情符号

### 网络限制
- AI 模型调用需要联网，处理过程中断网应有重试机制
- 大量截图上传时需要考虑网络带宽

### 技术限制
- OCR 对微信截图中的文字识别准确率受截图质量影响
- 多模态大模型对长截图（多轮对话）的理解能力有限，可能需要分段处理
- 同一客户的多张截图需要正确关联（依赖截图顶部的客户名称）

## 11. 容易出错的特殊情况

| 情况 | 说明 | 应对策略 |
|------|------|----------|
| 客户说「跟上次一样」 | 系统没有历史数据，无法确定具体参数 | 标注为不确定，列入人工确认 |
| 客户分多条消息说同一件事 | 如「45L」「大号」「带盖」分三条发 | 合并为完整规格描述 |
| 客户同时咨询多个商品 | 一条对话中提到多种商品 | 拆分为多条记录 |
| 数量表述模糊 | 如「再来一批」「老样子」 | 标注为不确定，列入人工确认 |
| 分批交货 | 如「先发60，剩下的下周」 | 数量取总数，交期栏记录分批信息 |
| 销售回复中包含确认信息 | 如「收到，改为米白色120个」 | 销售确认内容可作为辅助判断，但以客户表述为最终依据 |
| 截图被裁剪，客户名称不可见 | 无法识别客户身份 | 标注为「未知客户」，列入人工确认 |
| 同一客户不同销售截图 | 不同销售与同一客户聊天 | 按客户名称合并，去重时注意时间顺序 |
| 表情包/图片消息混在对话中 | 不影响文字提取 | 忽略非文字内容 |
| 客户用语音消息 | 截图无法识别语音内容 | 标注「含语音消息，部分内容可能缺失」 |
