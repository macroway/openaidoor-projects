# 不要只测答案：办公智能体评测的四层框架

作者：清远研究组（虚构）｜发布日期：2026-06-18｜原文标识：TRAINING-ARTICLE-017

很多团队评测办公智能体时，只看最终答案“像不像”。这种方法会遗漏两个更重要的问题：它是否读全了输入，以及过程是否可复核。

第一层是输入理解。评测者应准备字段缺失、日期冲突、重复记录和不同格式的样本，观察系统能否先发现问题。输入理解失败，后面的精美图表没有意义。

第二层是过程约束。办公任务通常含业务规则，例如 A/B/C 商机评级或指标口径。评测不应只问结果对不对，还应检查每个判断能否回到规则与原始记录。

第三层是交付物质量。这里同时包含结构正确、计算一致、文件可打开和视觉可读。视觉只是其中一项。一个漂亮但总数对不上的看板不应通过。

第四层是人工接管。高风险环节必须提供待确认项、异常清单和修改入口。系统表达不确定性并不代表能力弱，反而是可用性的组成部分。

四层并非每次等权。低风险的格式转换可以减少人工检查；招聘、财务、客户隐私等场景必须提高过程与人工接管权重。评测框架也不能替代真实用户测试，因为实验样本无法覆盖组织流程中的权限、协作和责任问题。

落地时可先选择一个 20–50 条记录的小任务，建立黄金样本与验收清单，再逐步增加噪音、规模和文件类型。每次失败都应记录在错误分类表，而不是只改提示语后忘记原因。
