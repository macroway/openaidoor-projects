# Case 05-01 提示语

## 使用前

- 将 `inputs/` 中列出的文件全部上传。
- 告诉 AI：“这些是课堂虚构/脱敏素材，只按附件处理。”
- 如工具无法读取某种格式，可使用同目录的 CSV、TXT 或 Markdown 备份。

## 主提示语

```text
【第一步：反馈归类整理】
请读取 5 个渠道的开发者反馈素材：
1. 提取有效反馈，去除“收到、+1、有人吗”等噪音；
2. 合并同一问题但保留全部来源和原始编号；不确定是否相同的不要强行合并；
3. 分类：Bug 修复/功能建议/体验优化/文档缺失/其他；
4. 每条标注来源渠道、独立用户数、提及次数、严重程度 P0–P3、建议优先级高/中/低和判断依据；
5. 输出表格，并总结 TOP3 主题、新增方向和建议动作。

【第二步：转需求描述】
筛选高优反馈，逐条生成需求标题、“作为…我希望…以便…”需求描述、2–3 条可验证验收标准和工作量 S/M/L。
不要把同一人的重复发言计算为多个独立用户。
```

## 追问提示语（演示校验与迭代）

```text
请列出所有被合并的反馈簇，每簇展示原始编号、合并后的标题以及判断它们属于同一问题的证据。
```

## 通用纠偏提示语

```text
请暂停生成新内容，先做质量审计：
1. 列出你使用的每个输入文件；
2. 标出所有事实、推断和待确认项；
3. 检查总数、比例、日期、字段映射和去重是否自洽；
4. 只修复能由附件证实的问题，不要补造数据；
5. 输出修订清单后再更新交付物。
```
